# 刃物交換指示システム

刃物交換指示表（手書き）の使用数をスマホから入力すると、工具寿命との比較から
**工場全体の刃物交換優先順位**を自動で並べ替えて共有するアプリです。

- 配布形式：**Webアプリ（PWA）**。ブラウザでURLを開くだけで使え、ホーム画面にも追加できます。
  iPhone/Androidどちらの私用スマホでも、アプリストアの審査なしですぐ使えます。
- データ共有：入力・送信した内容は**工場全員がリアルタイムで閲覧**できます
  （Firebase Realtime Database で共有。クレジットカード登録なしで使える無料プランです）。
- アクセス制限：**工場共通のパスコード**を入力しないとアプリ本体・データのどちらにも触れません
  （詳しくは「3. ログイン用のパスコードを設定する」）。

---

## セキュリティについて（必ずお読みください）

- **パスコード認証**：Firebase Authenticationで、工場共通のパスコードを知っている人だけがログイン
  できます。ログインするまでRealtime Databaseのデータには一切アクセスせず、工具マスタの初期データ
  （`masterData.js`）もネットワークから読み込みません。
- **Realtime Databaseのルール**：上記3-3の設定により、ログイン済みユーザーだけが読み書きできます。
  この設定を忘れる（ロックモードのまま、またはルールを緩めたまま公開する）と、URLとFirebase設定値を
  知っていれば誰でも読み書きできてしまうので、**必ず3-3まで設定してから工場のみんなに共有してください**。
- **できていないこと（限界）**：これは「全員が同じ1つのパスコードを共有する」簡易的な認証です。
  個人ごとのアカウントではないため、誰が何を送信・変更したかを完全に特定することはできません
  （記入者名は自己申告です）。また、私用スマホ自体のセキュリティ（画面ロック・OSの更新・紛失時の
  対応など）は会社側で管理できないため、機種変更や退職時にはアプリのログアウト・パスコードの
  変更を行ってください。より厳密な個人認証や操作ログが必要になった場合は、追加の実装で対応できます。

## 1. Firebaseプロジェクトを作る（無料・カード登録なし）

データの保存・共有には Google の Firebase（無料枠）を使います。

> **補足**：データベースには Firebase の中でも **Realtime Database** を使っています。
> もう一つの選択肢である Cloud Firestore は、現在は無料プランでも請求先アカウント
> （クレジットカード）の登録が必須になってしまったため、カード登録なしで使える
> Realtime Database を採用しました。

1. https://console.firebase.google.com/ にアクセスし、Googleアカウントでログイン
2. 「プロジェクトを追加」→ プロジェクト名を入力（例：`hamono-koukan`）→ 作成
3. 左メニューの「構築」→「**Realtime Database**」→「データベースを作成」
   - ロケーションは候補にあるものでOK（`asia-northeast1` がなければ他の候補で問題ありません）
   - セキュリティルールは「**ロックモード**」のまま作成してOK（後述の3-3でルールを設定します）
4. 左メニューの「プロジェクトの概要」の横にある `</>` アイコン（ウェブアプリを追加）をクリック
   - アプリのニックネームを入力（例：`hamono-app`）→ 登録
   - 表示された `firebaseConfig = { apiKey: ..., ... }` の中身をコピー
   （`databaseURL` という項目が含まれているはずです。含まれていない場合は、プロジェクト設定の
   「全般」タブから「マイアプリ」→ 該当アプリの設定を開き、もう一度SDKの構成を確認してください）

## 2. アプリに設定値を貼り付ける

[app/js/firebase-config.js](app/js/firebase-config.js) を開き、`firebaseConfig` の中身を
1.でコピーした値に置き換えて保存してください。`databaseURL` の行も忘れずに含めてください。

```js
export const firebaseConfig = {
  apiKey: "コピーした値",
  authDomain: "コピーした値",
  databaseURL: "コピーした値",
  projectId: "コピーした値",
  storageBucket: "コピーした値",
  messagingSenderId: "コピーした値",
  appId: "コピーした値",
};
```

## 3. ログイン用のパスコードを設定する

社内限定での利用にするため、**工場共通のパスコードでログインしないと使えない**仕組みにしています。
Firebase Authentication（無料）にパスコード用のアカウントを1つ作成し、Realtime Databaseのルールで
ログイン済みユーザーだけがデータにアクセスできるようにします。

### 3-1. メール／パスワード認証を有効にする

1. Firebaseコンソール → 左メニュー「構築」→「Authentication」→「始める」
2. 「Sign-in method」タブ → 「メール／パスワード」を選択 → 有効にする → 保存

### 3-2. パスコード用のアカウントを1つ作る

1. 「Authentication」→「Users」タブ →「ユーザーを追加」
2. メールアドレス：[app/js/firebase-config.js](app/js/firebase-config.js) の
   `SHARED_LOGIN_EMAIL`（初期値 `staff@hamono-app.local`）と**同じ文字列**を入力
   （実在するメールアドレスである必要はありません。変更したい場合は両方を書き換えてください）
3. パスワード：**工場のみんなで使う共通パスコード**を入力 → ユーザーを追加

これで、アプリを開いた人はこのパスコードを入力しないと中に入れなくなります。

### 3-3. Realtime Databaseのセキュリティルールを設定する

「Realtime Database」→「ルール」タブで以下に置き換えて「公開」してください。
**ログイン済みのユーザーだけ**が読み書きできるようになります。

```json
{
  "rules": {
    "products": {
      ".read": "auth != null",
      ".write": "auth != null"
    },
    "scans": {
      ".read": "auth != null",
      ".write": "auth != null",
      ".indexOn": "capturedAt"
    },
    "staff": {
      ".read": "auth != null",
      ".write": "auth != null"
    }
  }
}
```

> すでに `products` と `scans` だけのルールを設定済みの場合は、`staff` の部分を追記して「公開」し直してください。
> （担当者管理機能を追加した際に増えた項目です。）

> **注意**：これはあくまで「全員が同じ1つのパスコードを共有する」簡易的な認証です。
> 誰が何を送信したかは本人申告の「記入者名」でしか記録されないため、なりすましは防げません。
> パスコードは口頭や社内限定の連絡手段で伝え、メール本文やチャットの公開チャンネルなど
> 外部に漏れやすい経路には書かないようにしてください。パスコードを変更したくなったら、
> Firebaseコンソールの「Authentication」→「Users」で該当ユーザーのパスワードを再設定できます。

## 4. 公開する（無料ホスティング）

`app` フォルダの中身をそのまま公開すれば動きます。おすすめは以下のどちらかです。

### 方法A：Netlify Drop（最も簡単・アカウント登録も不要）

1. https://app.netlify.com/drop を開く
2. `app` フォルダをブラウザにドラッグ＆ドロップ
3. 発行されたURL（例：`https://xxxx.netlify.app`）を工場のみんなに共有

以後、内容を更新したときは同じ手順でもう一度 `app` フォルダをドロップすれば上書きされます。

### 方法B：Firebase Hosting（Firebaseに慣れている場合）

Firebase CLI（Node.js が必要）が使える環境であれば、`firebase init hosting` → 公開ディレクトリを
`app` に指定 → `firebase deploy` でも公開できます。

## 5. スマホでの使い方

1. 発行されたURLをスマホのブラウザ（Safari/Chrome）で開く
2. 「共有」→「ホーム画面に追加」（iPhone）／ ブラウザメニュー→「ホーム画面に追加」（Android）
3. ホーム画面のアイコンから、通常のアプリのように起動できます
4. 初回は工場共通のパスコード入力画面が出るので入力してください（一度入れれば、その端末では
   ログアウトするまで再入力不要です）

画面上部のヘッダー（アプリ名の右側）に、いつでも使える「🔄 更新」「ログアウト」ボタンがあります。
「更新」は画面を最新の状態に読み込み直すボタンです。表示がおかしい・更新が反映されていないと
感じたときに押してください。

### 担当者の登録（初回のみ）

「マスタ管理」タブの「担当者管理」から、担当者ごとに氏名・担当製品・担当NC機を登録しておくと、
「入力」タブで名前を選ぶだけで製品とNC機が自動で設定されるようになります。担当が変わったときは、
このタブでいつでも変更できます。まだ登録していない場合や、一時的な代打の場合は「その他（自由入力）」
を選べば、名前を直接入力して使えます。

### 入力の流れ

「入力」タブで担当者を選ぶ（または「その他」で名前を入力する）と、製品欄が自動で設定されます
（必要であれば変更もできます）。「⌨️ 表に直接入力する」を押すと入力画面に進みます。

1. 工具×NC機のマス目が並んだ表が表示されます（前回送信した値が最初から入っています）
   - 担当者に担当NC機が登録されている場合は、その機械の列だけが表示されます
2. 使用数が変わったNC機の欄だけ書き換えます（変わっていない機械はそのままでOK）
3. 一部のNC機だけ入力して送信することもできます（全機分そろっていなくても送信可能）

最後に「この内容で送信する」を押すと「優先順位」タブに即座に反映されます。
**欄を空欄のまま送信した場合、その工具・NC機の組み合わせは「データなし」として扱われ、
優先順位一覧には表示されなくなります**（誤って空欄にしたまま送信してしまった場合は、
もう一度正しい数値を入力して送信し直してください）。

### 優先順位タブの見方

- **正常（緑）になった工具は一覧に表示されません。** 「✅ 交換した」を押した工具や、
  もともと残り寿命に余裕がある工具は一覧から自動的に外れます（上部の「正常」のタイルには
  件数として残ります）。表示されている一覧には、対応が必要な工具だけが並びます。
  現在すべて正常な場合は「現在、交換が必要な工具はありません 🎉」と表示されます。
- **あなたの設定**：初めてアプリを開いたとき（またはまだ選んでいないとき）、担当者を選ぶ画面が
  出ます。選ぶと、画面上部に「👤 ◯◯さん」と表示され、「自分の担当分だけ表示」というチェックが
  出るようになります（担当製品・NC機が登録されている場合のみ）。チェックを入れると、優先順位が
  自分の担当分だけに絞り込まれ、番号も自分の担当分の中での順位に振り直されます。チェックを外せば
  工場全体の一覧に戻ります。上部の「変更」から、いつでも担当者を選び直せます。データそのものは
  全員で共有されたままなので、他の人の担当分もチェックを外せばいつでも確認できます。
- 「自分の担当分だけ表示」のチェックを外して工場全体を見ているときは、各カードに
  「👤 担当: ◯◯」という行が表示され、誰の担当分かが分かるようになっています
  （担当者が登録されていない場合は「👤 担当者未設定」と表示されます）。
- カードの左端の番号が交換の優先順位です。まず色（赤→黄→緑）の順にグループ分けされ、
  同じ色の中では、時間の見積もりがある工具ほど（＝早く尽きるものほど）上に表示されます。
  色と番号の順番が食い違うことはありません。
- **NC機にサイクルタイムを設定していない場合**：割合で判定します。
  赤：残り10%未満（至急交換）／ 黄：残り30%未満（まもなく交換）／ 緑：正常。
  「本日中に寿命到達の恐れ」は、1日の生産数（マスタ設定）を消費すると寿命を超える工具に表示されます
- **NC機にサイクルタイムを設定している場合**：割合ではなく、稼働カレンダー（1直/2直・土日休み）
  に基づく時間の見積もりで判定します（割合とシフト判定が食い違って矛盾した表示にならないよう、
  サイクルタイムが分かっている機械はこちらを優先します）
  - **使用数のカウンターが自動で増えていきます。** 最後に記録した使用数と時刻をもとに、
    そこから実際に稼働していた時間 ÷ サイクルタイムぶんだけ、使用数を自動的に見積もって
    表示します。数値の横に「推定」というラベルが付きます（人が確認した実際の値ではなく、
    時間から計算した見積もりという意味です）。画面を開いたまま数十秒待つと、この推定値が
    自動的に増えていくのが確認できます。実際に数値を入力して送信すると、その時点の
    正確な値に置き換わります。
  - 「⏱ 残り約◯時間◯分（目安 ◯/◯(月) ◯:◯）」という見積もりが表示されます
  - 🔴 赤「⏰ 今のシフト中に交換が必要」：今のシフト（1直/2直）中に寿命に達する見込み
  - 🟡 黄「🟡 次のシフトまでに交換が必要」：今のシフト中は持つが、次のシフト中には寿命に達する見込み
  - 🟢 緑「✅ 今のシフト中は交換不要」：次のシフトまでは寿命に達しない見込み
    （その先いずれ交換が必要になる点にはご注意ください）
  - 稼働カレンダーの前提：1直 8:00〜21:00／2直 21:00〜翌8:00、土日休み、
    金曜の2直のみ土曜4:00で終了（土曜が休みのため）

### 「担当別」タブ

担当製品・NC機が登録されている担当者ごとに、🔴至急／🟡まもなく／🟢正常の件数をまとめて
一覧表示します。至急交換が多い人が上に並ぶので、工場全体で誰の負荷が高いかをひと目で
確認できます（担当者本人だけでなく、管理者が全体を見渡すのにも使えます）。

**カードを押すと、その人の担当分だけに絞った「優先順位」一覧にジャンプできます。**
（自分の「あなたの設定」は変更されません。一覧上部の「閉じる」を押すか、他のタブに
移動すると元の表示に戻ります。）

### 工具を交換したとき

各カードの下にある「✅ 交換した」ボタンを押すと、担当者一覧から選ぶ画面が出ます
（未登録の方は「その他（自由入力）」から名前を入力できます）。選ぶと、その工具の
使用数だけが0にリセットされ、優先順位から外れます（残り100%＝正常になり、一覧の下の方に移動します。
同じ機械の他の工具の数値は変わりません）。押し間違えた場合の取り消し機能はないため、間違えて押した
ときは「入力」タブから正しい使用数を入力し直してください。

### マスタ管理タブ

「担当者管理」と「製品・工具マスタ」は上部のボタンで切り替える別々の画面になっています。
この切り替えボタンは画面上部に固定されているので、一覧を下までスクロールしても、
わざわざ一番上まで戻らずに切り替えられます。
それぞれの画面の下部に、その画面専用の「まとめて保存」ボタンと「選択して削除」ボタンがあります。

- **まとめて保存**：カード1件ごとの保存ボタンはありません。何件編集・追加しても、最後に
  画面下の「💾 まとめて保存」を1回押せば、表示されている内容がすべて保存されます
  （カード左上の「削除選択」チェックボックスは削除する項目を選ぶためのものなので、
  チェックを入れていない項目も含めて全て保存されます）。
- **選択して削除**：削除したいカードの左上にある「削除選択」チェックボックスにチェックを入れ、
  画面下の「選択した◯◯を削除」を押すと、チェックした分だけまとめて削除されます
  （確認ダイアログが出ます）。「全て選択/解除」で一括チェックもできます。

**担当者管理**：担当者の氏名・担当製品・担当NC機を登録・変更・削除できます。
担当製品を選んだら、**必ずその製品の担当NC機にもチェックを入れてください**（1台もチェックしないままだと、
その製品は「担当」として一切カウントされず、優先順位タブの「担当:」表示や「自分の担当分だけ表示」の
絞り込みに出てきません）。

**製品・工具マスタ管理**：初期状態では、同梱の `刃物交換指示表　.xlsx` から読み取った1製品分のデータ
（工具番号・加工工程・メーカー・型式・工程数・工具寿命・対象NC機）が入っています。
フォルダー内の他の指示表も、このタブから製品を追加して同じように登録できます。
各NC機ごとに「サイクルタイム（1個あたりの加工秒数）」を入力すると、優先順位タブに
時間ベースの見積もりが表示されるようになります（未入力でも従来通り割合ベースで動作します）。
NC機は「＋ NC機を追加」から何台でも自由に追加できます。

**工具の一括追加**：工具を1件ずつ入力するのが手間な場合は、工具一覧の下にある
「📋 Excel等から一括追加」から、Excelなどでコピーした表を貼り付けて追加できます。

1. Excelで工具の表を選択してコピーし（ふりがな用の隠れた列や、見出し行が混ざっていても大丈夫です）、
   貼り付け欄にそのまま貼り付けて「次へ」
2. 表の各列が「工具No・加工工程・メーカー・型式・工程数・寿命」のどれに対応するかを、
   列ごとのプルダウンで選ぶ（使わない列は「使用しない」のままでOK）。
   **「工具No」の列だけは必ずどれか1つ選んでください**（選ばずに次へ進むとエラーになります）
3. 1行目が見出し行の場合はチェックを入れる
4. 「この内容を追加する」で一括反映（画面下の「まとめて保存」を押すまでは確定しません）

列の並び順や、余分な列が混ざっていても、貼り付け後の画面で列の意味を選び直せるので、
どんな表からでも安全に取り込めます。

**製品の複製**：似た製品を新しく登録したい場合は、既存の製品カードの「複製」ボタンを押すと、
NC機・工具一覧をコピーした状態で新しい製品を作成できます（新しい製品IDだけ入力すればOKです。
複製されたカードも、画面下の「まとめて保存」を押すまでは確定しません）。

## オフラインキャッシュ（Service Worker）を廃止しました

以前はオフラインでも画面の骨組みだけは開けるように、Service Workerというブラウザの仕組みで
アプリの中身をキャッシュしていました。しかし、更新するたびに古いキャッシュが端末に残ってしまい、
最新版が反映されない・キャッシュを手動で消さないと直らない、という問題が繰り返し起きたため、
この仕組み自体を廃止しました。今後、アプリを更新した際に反映されないことがあれば、単純に
GitHubへのアップロードが正しくできているか（または少し待って再読み込みするか）だけを
確認すれば大丈夫です。

既にService Workerが登録されてしまっている端末については、`app/sw.js`
に「後片付け専用」のコードを用意しました。ブラウザが自動的に更新を検知したタイミングで、
古いキャッシュとService Worker自体を自動的に削除し、ページを最新の状態に読み込み直します。
ただし、この自動検知には端末やブラウザによって時間がかかることがあるため、すぐに反映させたい
場合は、次の手順でその場で強制的にリセットできます（Chromeの場合）。

1. アプリを開いた状態で `F12` キーを押す（開発者ツールが開きます）
2. 上部のタブから「Application」（見当たらなければ「>>」の中）を選ぶ
3. 左側のメニューの「Storage」の中にある「Clear site data」ボタンを押す
4. 開発者ツールを閉じて、ページを再読み込みする

## 動作確認について（開発メモ）

このアプリは、開発環境にNode.js/Pythonが無い状態で作成しました。優先順位の判定・並べ替えロジックは、
実際のコードと同一のロジックを別エンジンで実行し、数値的に正しいことを確認済みです（14件のアサーション
全て合格）。稼働カレンダー（1直/2直・土日休み・金曜のみ土曜4:00終了）の計算ロジックも同様に別エンジンで
実行し、23件のアサーション全て合格しています。一方で、Realtime Databaseとの同期・パスコードログインに
ついては、Firebaseプロジェクトの設定（上記1〜3）が完了した状態でしか確認できないため、
**公開後に一度実際のスマホで一通り試してください**。ログイン画面が出ない・パスコードを入れても
弾かれる場合は、3-1（メール／パスワード認証の有効化）と3-2（ユーザー作成時のメールアドレスの一致）
を再確認してください。

## ファイル構成

```
app/
  index.html            画面本体
  css/style.css         スタイル
  js/app.js             画面制御・入力フロー
  js/db.js              Realtime Database読み書き
  js/priority.js        優先順位の計算
  js/schedule.js         稼働カレンダー（1直/2直・土日休み）とサイクルタイム見積もり
  js/masterData.js       初期マスタデータ（xlsxから抽出）
  js/firebase-config.js  ← ここにFirebase設定・ログイン用メールアドレスを設定
  manifest.json / sw.js  PWA設定
  icons/                 アプリアイコン
```
